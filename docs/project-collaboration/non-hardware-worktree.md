# 非真机组统一协作模式

## 一句话原则

> 一个项目、一个组织仓库、一个共享 `main`；每人一个个人 worktree，所有项目内容不出 worktree，定期同步并把成熟成果合入 `main`。

## 用途

本规范用于管理非真机组课题中的代码、实验配置、脚本、笔记和阶段性成果，减少个人 clone、仓库外临时目录和未推送提交带来的迁移与清理风险。

## 适用范围

- 本规范适用于所有非真机组。
- 当前覆盖世界模型组和仿真组的课题协作。
- 后续新增非真机组时，默认沿用本规范，除非项目负责人发布经过审核的补充规则。
- 真机组还需遵守设备、校准、实时控制和实验数据的额外安全边界；本页不替代这些要求。

## 前置条件

- 项目只使用一个组织仓库，并已确定仓库维护者和项目负责人。
- 公共 workspace 已准备好共享 `main`、Git 元数据和公共资源。
- 每位成员有自己的项目 workspace、个人分支和必要的仓库权限。
- 项目负责人已确认大型数据、checkpoint、缓存和运行结果统一使用 worktree 根目录下的 `data/`，并约定其清单格式。
- 仓库内的 `.gitignore` 已使用根锚定的 `/data/` 规则排除该目录，且不会误排除源码中的同名子目录。

## 目录与分支模型

公共目录只承载共享 `main`、Git 元数据和公共资源：

```text
/home/<SHARED_ACCOUNT>/workspace/<REPO>/
```

成员在自己的 workspace 中使用独立 worktree：

```text
/home/<MEMBER_NAME>/<REPO>/  ->  worktree/<MEMBER_NAME>
```

其中：

- `/home/<SHARED_ACCOUNT>/workspace/<REPO>/` 是项目唯一的共享仓库入口，不用于个人实验。
- `/home/<MEMBER_NAME>/<REPO>/` 是成员日常工作的个人 worktree，个人代码和实验材料都留在这里。
- `worktree/<MEMBER_NAME>` 是个人工作分支的示例命名；同一仓库内应保持命名唯一且可追踪。
- 禁止为同一项目创建个人 GitHub 仓库，或长期维护第二套独立 clone。

## 日常协作流程

1. 从共享 `main` 创建或更新个人 worktree 和个人分支；开始工作前确认远端和当前分支指向正确的组织仓库。
2. 在个人 worktree 内完成代码、实验配置、脚本、笔记和阶段性成果，不把项目文件放到仓库外的临时目录、Documents 或个人 clone。
3. 完成一个可复查的变更后及时提交，并将个人分支推送到组织仓库；提交信息应能说明变更目的或实验阶段。
4. 定期从 `main` 获取更新，并按项目约定完成合并或变基；同步后重新运行受影响的检查和实验。
5. 只有经过验证、可供全组复用的通用功能才提交 Pull Request 并申请合入 `main`。
6. 未完成的实验、仅用于当前假设的脚本和不稳定配置继续保留在个人分支，不以“暂时可用”为理由进入 `main`。

## 大型文件与实验产物

- 大型数据、checkpoint、缓存和运行结果不直接进入 Git，统一保存在项目 worktree 内被忽略的 `data/` 目录；不要另建用途相同的顶层目录。
- 使用 `.gitignore` 排除本地产物；不要用仓库外目录替代 `data/`，也不要把被忽略的文件当成唯一备份。
- 为每个重要数据集或结果保存可提交的 manifest，至少记录来源、版本或生成提交、文件数量和总大小、校验哈希、负责人、许可或访问边界、保存位置和最后核验日期。
- 需要共享或复现实验时，提交配置、脚本、README 和 manifest；不要提交数据本体、认证信息或私密下载链接。
- 重要本地数据应有项目认可的集中副本或备份；清理个人 worktree 前先确认备份可读且与 manifest 一致。

## 合入 `main` 的条件

进入共享 `main` 前，变更必须同时满足：

- 代码、配置或文档已经过项目负责人或指定维护者复查。
- 相关检查、最小复现实验或评测已经通过，并记录必要的运行环境和结果。
- 变更对全组有明确复用价值，不只是未完成实验的临时状态。
- 不包含认证凭据、个人身份信息、受限数据或未经批准的内部地址。
- 大型产物已被 `.gitignore` 排除，manifest、哈希和来源说明已进入 Git。
- 合入后不会破坏其他成员正在使用的稳定流程；必要时在项目变更记录中说明迁移方式。

## 清理前检查

删除旧目录、分支或实验材料前，必须完成以下检查：

1. 在目标 worktree 中运行 `git status --short`，确认没有未提交的项目文件。
2. 查看本地和远端分支的提交关系，确认独有提交已经推送，且已被活动分支或 `main` 覆盖。
3. 对 `data/` 和其他历史遗留的被忽略目录核对 manifest、校验哈希和备份状态；遗留目录迁移完成后不再继续使用。
4. 让项目负责人确认该目录、分支或实验材料不再被其他成员、任务或复现实验使用。
5. 记录清理对象、确认人和日期；发现任何一项无法确认时暂停清理并保留原材料。

## 验证清单

每次交接、迁移或阶段性收尾时，确认：

- 成员能定位项目唯一组织仓库和共享 `main`。
- 每位成员都能定位自己的 worktree、个人分支和远端分支。
- `git remote -v` 指向组织仓库，没有个人仓库或长期第二 clone。
- 代码、配置、脚本和笔记都在个人 worktree 内，并已按阶段提交和推送。
- 大型本地产物统一位于 worktree 的 `data/` 目录内，Git 状态不误报为待提交文件。
- 重要数据有 manifest、哈希、来源说明和可验证的备份。
- 计划合入 `main` 的功能已经过验证，未完成实验仍留在个人分支。

## 故障排查

- **误建了个人 clone：** 立即停止在第二套 clone 中继续开发，核对远端、未推送提交和未纳入清单的本地数据，再迁移到项目分配的 worktree；迁移完成并确认覆盖关系后，不再长期维护第二套 clone。
- **文件散落在 worktree 外：** 暂停清理和迁移，先把项目文件、配置和笔记归拢到个人 worktree，并为大型数据补齐 manifest 或备份；不要把临时目录当作项目归档位置。
- **个人分支长期落后 `main`：** 获取最新 `main`，按项目约定合并或变基，逐项解决冲突并重新运行受影响的检查；不要直接覆盖他人的提交。
- **大型文件被误跟踪：** 先保留可恢复的本地副本，补充 `.gitignore` 和 manifest，再按维护者批准的方式从 Git 索引或历史中移除；不要在未确认备份前删除唯一副本。
- **清理时发现未推送提交：** 立即停止删除，检查提交内容和敏感信息，推送到个人远端分支并确认远端可见，再重新进行覆盖关系检查。
- **无法确认负责人、分支覆盖或数据备份：** 暂停操作，通过受控通讯录联系项目负责人或仓库维护者；确认前不删除、不强制覆盖、不公开数据。
