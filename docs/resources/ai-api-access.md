# AI API 申请与使用

!!! info "使用 API 前请确认"
    请使用个人获批的 API key，切勿在 Wiki、代码或聊天中粘贴凭据。

!!! danger "地址可公开，凭据不可公开"
    Wiki 可以记录 API Base URL、服务主页和负责人，但不得记录 API key、访问 token、密码、Cookie、请求头或个人用量明细。

## 用途

为已获批准的实验室科研项目申请和使用实验室管理的 AI API，并在可追踪的个人额度内完成模型调用。

## 前置条件

- 已加入明确的实验室科研项目，并获得项目负责人同意。
- 已确认任务确实需要实验室 API；个人学习和日常使用应优先使用个人工具。
- 已估算模型类型、调用规模、预计周期和是否需要高并发或多 Agent。
- 已阅读实验室的数据安全、代码提交和凭据管理要求。

## 申请信息

| 字段 | 说明 |
|---|---|
| 项目 | 所属科研项目及负责人角色 |
| 用途 | 计划完成的研究任务 |
| 模型需求 | 所需模型类别或能力，不填写密钥 |
| 数据边界 | 是否包含未公开研究数据或其他受限内容 |
| 申请人 | 个人账户标识；每人使用独立凭据 |

## 操作步骤

1. 联系 `@_嗯` 或 `@赖咏曦`，提交上表信息。
2. 管理员确认科研用途、额度、模型权限和数据边界。
3. 通过获批的密码管理器或一次性安全渠道接收个人 key。
4. 仅在本机环境变量或获批的密钥管理系统中配置凭据，例如：

    ```bash
    export LAB_AI_BASE_URL="https://kjapi.botsmart.net"
    export LAB_AI_API_KEY="<AI_API_KEY>"
    ```

5. 使用管理员提供的最小测试模板验证连接，不在日志中打印请求头或环境变量。
6. 确认测试调用已计入个人用量后，再开始正式任务。

## 使用规范

- 凭据按用户分配并进行流量监控，禁止共享、转发或代他人使用。
- 仅用于获批科研项目，禁止用于与项目无关的日常任务。
- 多 Agent、长时间运行和高并发任务可能快速消耗额度，启动前应评估预算并取得批准。（不要使用Goal 模式！）
- 不得把未脱敏的个人信息、受限数据或未公开材料发送给未经批准的模型服务。
- 不得在 Notebook、Shell 历史、训练日志、错误截图或 Git 提交中保留 key。

## 验证

- 最小测试返回预期模型结果，且未在终端或日志中显示凭据。
- 管理员侧能够看到对应个人账户的用量记录。
- 代码仓库和文档可以记录 `https://kjapi.botsmart.net`，但 key 只能使用 `<AI_API_KEY>` 等占位符。

## 故障排查

| 现象 | 处理方式 |
|---|---|
| `401` 或 `403` | 检查本机变量是否加载，并联系管理员确认权限；不要发送 key 截图 |
| `429` 或额度不足 | 降低并发、停止非必要任务，并申请额度复核 |
| 请求超时 | 记录时间、模型和请求 ID，检查网络后再向管理员报告 |
| 用量异常 | 立即停止调用、吊销并轮换 key，随后审计近期使用记录 |
| 凭据进入 Git 历史 | 立即通知管理员轮换；删除当前文件不足以消除历史泄露 |
