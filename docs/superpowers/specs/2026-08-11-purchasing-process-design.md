# 采购流程规范设计

## 目标

将现有采购占位页扩写为实验室各组可重复执行的统一流程，覆盖选型、提交、汇总、采购、到货认领和拍照入库。流程需要减少重复采购、型号不兼容和采购后闲置，同时明确公开 Wiki 与内部采购记录的边界。

## 页面范围

- 原位更新 `docs/administration/purchasing.md` 和 `docs/administration/purchasing.en.md`，保持中英文内容一致。
- 更新中英文行政总览，将“示例”改为正式流程表述。
- 不新增导航项，不在 Wiki 中保存真实购物车分享链接、订单、报价、付款信息、个人地址或采购照片。

## 角色

- **各组成员**：共同讨论需求、完成选型和可行性调研。
- **各组采购提交人**：整理本组每周唯一一份采购清单和共享购物车链接，并在截止时间前提交。
- **采购协调人**：在周六、周日汇总各组提交，检查字段、重复采购、审批状态和明显风险。
- **采购执行人**：在下一周按已确认内容下单，并把到货包裹放到公共区域。
- **物品所属组**：认领包裹，逐项核对、拍照并在受控资产登记系统完成入库。

角色使用通用名称，不公开个人姓名或联系方式。

## 流程

1. 同组成员共同明确采购目的，比较可选型号并完成兼容性、交付和实际使用可行性调研。
2. 选型后，由本组采购提交人整理一份周采购清单。每项至少记录物品名称、数量、型号或规格、商品链接、采购目的和调研结论；清单还应记录所属组、提交周和必要的审批状态。
3. 将拟采购物品加入淘宝或其他供应商网站的购物车，生成共享购物车链接，并通过实验室指定的受控渠道与清单一起提交。
4. 每组每周只提交一次。采购协调人在周六、周日汇总，缺失字段、重复采购、审批未完成或可行性不足的项目退回补充；通过检查的项目安排在下一周采购。
5. 采购执行人按确认后的型号、数量和链接下单。商品发生缺货、涨价或规格变化时不得自行替换，应退回所属组重新确认。
6. 到货包裹放在实验室指定公共区域。所属组自行认领并逐项核对名称、型号、数量和外观状态。
7. 所属组为每项物品拍照，并在受控资产登记系统中完成入库。照片和内部资产记录不提交到公开 Wiki。

## 调研与审批要求

每项采购必须说明明确用途，并确认与现有设备、软件、接口、尺寸、电源或实验方案兼容。提交人还应说明预计使用人和使用时间，避免购买后无法使用或长期闲置。

金额较高的采购需要更充分地比较备选方案、验证关键兼容性、说明使用计划，并按实验室现行审批规则取得事前确认。由于当前需求未给出统一金额阈值，Wiki 不自行设定数值；具体阈值以实验室现行审批要求为准。

## 清单模板

采购页提供可复制的 Markdown 表格，字段包括：

- 物品名称
- 数量
- 型号或规格
- 商品链接
- 采购目的
- 调研结论
- 审批状态

清单顶部另行记录所属组、提交周、采购提交人角色和共享购物车链接。示例只使用占位值，避免公开真实订单或成员信息。

## 核验与异常处理

页面按仓库操作指南规范加入以下检查点：

- 提交前核验字段完整、组内选型已确认、链接可访问、审批状态符合要求。
- 汇总时核验每组每周仅一份清单，并检查重复采购和明显不兼容风险。
- 到货时核验实物与订单一致，逐项拍照并完成受控资产登记。
- 对缺货、价格或规格变化、错发漏发、破损、无法认领、无法入库等情况给出暂停处理和升级路径。
