# 非真机组统一协作模式设计

## 背景

世界模型组和仿真组需要统一管理各自课题的代码、实验配置、脚本、笔记和本地大型产物。当前约定的核心是：每个项目只维护一个组织仓库和一个共享 `main`，成员通过独立 worktree 在个人 workspace 中工作，成熟成果再合入 `main`。

这项规范描述课题研发协作，不是向 Lab Wiki 投稿的流程，因此不放在“如何贡献”栏目中。

## 目标

- 为所有非真机组提供统一、可执行的 Git 与目录协作规范。
- 明确当前适用对象为世界模型组和仿真组，并允许未来新增非真机组直接沿用。
- 降低个人 clone、仓库外散落文件、未推送提交和本地实验数据在迁移或清理时丢失的风险。
- 说明个人分支、共享 `main`、大型本地产物和清理前检查之间的边界。
- 同步提供中文和英文页面，并保持两种语言的导航一致。

## 非目标

- 不规定各课题的研究路线、实验方法或代码架构。
- 不提供真实成员姓名、账号、内部仓库地址或其他敏感信息。
- 不替代真机组的设备、校准、实时控制和实验数据安全规范。
- 不在本次改动中创建 worktree 自动化脚本或改造现有仓库布局。

## 页面结构

中文和英文页面采用相同结构：

1. 一句话原则：一个项目、一个组织仓库、一个共享 `main`；每人一个个人 worktree，所有项目内容不出 worktree，成熟成果定期合入 `main`。
2. 用途：解释规范要解决的协作、迁移和数据保存问题。
3. 适用范围：面向所有非真机组，当前覆盖世界模型组和仿真组；真机组另有额外安全边界。
4. 前置条件：项目已有组织仓库、共享 workspace、个人账号和写入权限，并确定项目负责人。
5. 目录与分支模型：用 `<SHARED_ACCOUNT>`、`<MEMBER_NAME>` 和 `<REPO>` 展示共享目录、个人 worktree 与 `worktree/<MEMBER_NAME>` 分支的对应关系。
6. 日常协作流程：在个人 worktree 中工作，及时提交和推送，定期同步 `main`，验证成熟功能后通过审核合入 `main`。
7. 大型文件与本地产物：数据、checkpoint、缓存和运行结果保留在 worktree 内的约定目录，通过 `.gitignore` 排除；可追踪的 manifest、哈希和来源说明进入 Git。
8. `main` 准入条件：只有全组共享、经过验证且不含敏感信息的内容才进入 `main`；未完成实验留在个人分支。
9. 清理前检查：确认提交和推送状态、独有提交覆盖关系，以及大型本地数据的 manifest 或备份，再删除旧目录、分支或实验材料。
10. 验证清单：成员能够定位唯一组织仓库、共享 `main`、个人 worktree、远端个人分支和本地产物说明。
11. 故障排查：覆盖误建个人 clone、文件散落仓库外、分支长期落后、误跟踪大文件以及清理前发现未推送提交等常见情况。
12. 维护信息：负责人使用角色名称，不公开个人联系方式；最后核验日期为 `2026-08-14`。

## 内容与安全边界

- 所有路径和仓库名均使用占位符，不写入真实用户名或未批准的内部仓库信息。
- 不记录 token、SSH 私钥、账号密码、内部数据集位置或未公开研究成果。
- 英文页面忠实表达中文规范，不增加或删除约束。
- 页面不要求大型数据进入 Git，只要求其保留在 worktree 的约定目录并具有可追踪说明或备份。
- 删除操作只提供检查要求，不提供批量或递归删除命令。
